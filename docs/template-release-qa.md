# 릴리스 QA 템플릿

> 문서 유형: 참조(reference) · 실행용 사본 템플릿

원본은 빈 체크리스트로 유지하고 매 릴리스 전에 저장소 밖에 복사합니다. 실행·복사 방법은
작업 저장소의 `docs/guide-visual-qa.md`를 참고합니다. 일반 작업은 아래 최소 스모크와 변경
관련 항목만 선택합니다. 릴리스는 적용 가능한 전체 기능을 확인합니다.

## 실행 범위

- 후보 버전 / 커밋 SHA:
- 이전 지원 버전 / 이번 릴리스의 호환·이전 정책:
- 작업 저장소 절대 경로:
- API·Worker 버전 / 테스트 origin:
- 후보 설치본·웹 빌드 / 해당 SHA의 CI 링크:
- 모드: 전체 릴리스 / 최소 스모크 + 변경 범위
- 변경 기능·선택 항목 ID(일반 QA):
- QA 계정 별칭 / 사용자가 허용한 조작 범위:
- 임시 결과물 경로:

`W`는 일반 웹, `D`는 Tauri PC 앱, `P`는 설치형 PWA입니다. 아래 환경의 버전과 실제 기기·
시뮬레이터 여부를 사본에 채웁니다. 공통 UI를 모든 환경에서 반복할 필요는 없지만,
설치·로그인·트레이·OS 알림·Push처럼 플랫폼에 의존하는 기능은 환경별 결과를 남깁니다.

### 기록 방법

- `[ ]`는 미실행, `[x]`는 정한 대상 환경에서 통과입니다. 사유 없이 미실행 항목을 지우지 않습니다.
- 실패는 `FAIL — 관찰 결과`, 준비 부족은 `BLOCKED — 필요한 계정/환경`, 비해당은 `N/A — 이유`를 행 끝에 씁니다.
- 환경별 결과가 다르면 체크를 남겨 두고 `D macOS: PASS / D Windows: BLOCKED`처럼 구분합니다.
- `(코드 가능)` 항목은 같은 SHA의 기존 테스트로 재현해도 됩니다. 명령·테스트 이름과 결과를 아래 근거 표에 연결합니다. 테스트 파일의 존재만으로 통과시키지 않습니다.
- 실제 화면은 에이전트가 관찰 → 조작 → 재관찰하며 판단합니다. fixture·개발 앱의 확인 결과는 실제 설치본·실데이터와 구분합니다.
- 계정 처리가 필요하면 QA 담당자 → 메인 → 사용자 순서로 준비와 허용 범위를 요청합니다. 이미 허용된 범위는 재사용하며 비밀번호·쿠키·토큰은 기록하지 않습니다.

WebDriver 준비 도구의 격리 복사본은 비영구 프로필이며 자동 시작·통계·업데이트를 제한합니다.
그 복사본으로는 실제 설치·세션 보존·자동 시작·업데이트 통과를 기록할 수 없습니다.

## 최소 스모크

- [ ] **SMK-01 실행** — 대상 앱/웹이 시작돼 기본 화면이 열리고 시작 실패나 무한 로딩이 없다.
- [ ] **SMK-02 탐색·조회** — 홈에서 공개 데이터 하나를 확인하고 변경 화면에 진입했다가 돌아올 수 있다.
- [ ] **SMK-03 대표 동작** — 변경 기능의 대표 조작을 한 번 수행해 기대 결과, 화면 잘림, 새 런타임 오류를 확인한다. 서버 변경은 해당 API·작업의 대표 요청으로 확인한다.

## 1. 공통 탐색·홈·사용성

환경: W/D/P. 개인 출석 요약은 계정이 필요합니다.

- [ ] **UI-01 경로** — 홈·출석·세탁실·급식 직접 진입, 새로고침, 뒤로/앞으로 이동 시 메뉴·제목·본문이 일치한다.
- [ ] **UI-02 설정 탐색** — 앱 상태·알림·서비스·기기 연결 탭을 열고 이동·복귀한다. 잘못된 탭은 앱 상태로 정리된다.
- [ ] **UI-03 경로 복구** — 알 수 없는 경로는 홈으로, 이전 `/#/setup`은 설치 안내로 이동한다. 외부 주소를 복귀 경로로 실행하지 않는다. (코드 가능)
- [ ] **UI-04 홈 요약** — 세탁 가능 수와 중식·석식 요약이 상세 화면과 일치하고 상세로 이동한다. 한 카드의 실패가 다른 카드 조회를 막지 않는다.
- [ ] **UI-05 플랫폼별 홈** — W는 앱 소개·설치 안내, D/P는 연결·출석·D-Day 상태를 표시하며 연결 전을 출석 완료로 표시하지 않는다.
- [ ] **UI-06 조회 상태** — 첫 로딩·빈 데이터·부분 실패·마지막 정상 데이터·오프라인을 구분한다. 재시도·새로고침 후 화면이 복구되고 중복 조작은 진행 중임을 표시한다.
- [ ] **UI-07 화면 크기** — PC 최소 창 크기와 모바일 좁은 화면에서 탐색·카드·대화상자·알림 패널을 끝까지 볼 수 있다. 키보드·안전 영역이 주요 버튼을 가리지 않는다.
- [ ] **UI-08 키보드·접근성** — 탐색·탭·입력·다이얼로그를 키보드로 조작한다. 이동 후 제목 포커스, 닫기 후 원래 포커스, 버튼·상태의 접근성 이름을 확인한다.
- [ ] **UI-09 테마·시간** — 시스템 밝은/어두운 테마 변경이 반영되고 텍스트·경고·상태가 식별된다. 기준일·절대 시각·상대 시각이 서로 모순되지 않는다.
- [ ] **UI-10 외부 링크** — GitHub·피드백·릴리스·급식 원문을 올바른 대상으로 연다. D의 외부 링크는 시스템 브라우저로 열린다.

## 2. 공개 웹·설치 안내·PWA 수명주기

환경: W/P. 실제 설치·업데이트는 production 빌드와 HTTPS 환경, 개인 세션·Push는 계정이 필요합니다.
웹 업데이트(PWA-04~06)는 production 일반 웹과 설치 PWA에 모두 적용됩니다.

- [ ] **WEB-01 공개 이용** — 비로그인 브라우저에서 홈·세탁·급식·기록·개인정보 안내를 조회한다.
- [ ] **WEB-02 개인 기능 안내** — W의 출석·알림·연결 진입은 설치 안내를, 미연결 P는 연결 안내를 제공한다. 개인 데이터를 노출하지 않는다.
- [ ] **WEB-03 플랫폼 구분** — 같은 URL의 일반 탭과 standalone PWA가 각자의 기능 범위를 사용한다. W는 개인 API를 호출하거나 개인 응답을 캐시하지 않는다. (코드 가능)
- [ ] **WEB-04 설치 안내** — PC·모바일 설치 단계, Android/iOS 탭, 안내 이미지 확대·닫기, PC 다운로드 링크가 동작한다.
- [ ] **WEB-05 설치 프롬프트** — 지원 환경의 설치·취소와 미지원·이미 설치됨 상태가 구분된다. 미지원 환경에는 수동 설치 안내가 있다.
- [ ] **PWA-01 설치 실행** — 홈 화면에 설치하고 아이콘으로 다시 열면 standalone으로 실행되며 앱 이름·아이콘·시작 화면이 맞다.
- [ ] **PWA-02 재실행** — 완전 종료·재실행 후 유효한 연결 세션과 개인 기능을 복원한다. 만료된 세션에는 재연결 안내를 표시한다.
- [ ] **PWA-03 오프라인·복구** — 캐시된 공개 화면과 오프라인 안내를 구분하고 재접속 후 새 데이터를 조회한다. 개인·인증 API를 Service Worker 캐시로 제공하지 않는다.
- [ ] **PWA-04 업데이트 대기** — 새 웹 빌드가 준비돼도 입력 중 자동 새로고침하지 않고 업데이트 적용을 안내한다.
- [ ] **PWA-05 업데이트 적용** — 명시적 적용 후 새 빌드가 열린다. 급식 알림 입력은 서버 기준값이 같으면 복원하고 달라졌으면 오래된 입력을 폐기한다. 입력 보존·SW 등록/활성화 실패 시 현재 화면을 유지하며 재시도할 수 있다.
- [ ] **PWA-06 자산 갱신** — 이전 캐시에서 새 배포로 이동할 때 JS/CSS·API 조합 때문에 흰 화면이나 무한 새로고침이 생기지 않는다.

## 3. PC 설치·창·설정

환경: D 실제 설치본. 최초 서버 등록·영구 프로필·OS 설정을 사용할 범위는 메인을 통해 준비합니다.

- [ ] **PC-01 새 설치** — 후보 설치본을 새 QA 프로필에 설치하면 대시보드·트레이가 나타나고 서버 PC 등록 상태를 확인할 수 있다.
- [ ] **PC-02 기존 버전 전환** — 이전 지원 버전에서 후보 버전으로 바꾼 뒤 identity·설정·연결·알림함을 이번 릴리스의 호환 정책대로 유지하거나 복구한다.
- [ ] **PC-03 중복 실행** — 실행 중 다시 실행하면 별도 인스턴스 대신 기존 대시보드가 열린다.
- [ ] **PC-04 창 수명주기** — 창 닫기는 트레이와 백그라운드 작업을 유지한다. 트레이 클릭·메뉴로 다시 열고, 메뉴 종료는 프로세스를 끝낸다.
- [ ] **PC-05 OS 창 동작** — 최소 크기·확대·복원·포커스와 Dock/작업표시줄 동작이 맞고 다른 창 뒤에서 다시 열 수 있다.
- [ ] **PC-06 트레이 상태** — 확인 중/불가·로그인 필요·출석 가능·학습 중·완료의 아이콘과 툴팁이 실제 상태 및 OS 테마에 맞는다.
- [ ] **PC-07 자동 시작** — 서비스 설정에서 켠 뒤 OS 로그인 시 백그라운드 실행되고, 끄면 자동 실행하지 않는다.
- [ ] **PC-08 설정 보존** — 기수·자동 시작·사용 통계·디버그 설정의 저장 성공/실패가 구분되고 재실행 후 저장값을 복원한다.
- [ ] **PC-09 디버그·지원** — 디버그 활성화 확인·취소·해제와 전용 로그 폴더 열기가 동작한다.
- [ ] **PC-10 절전·연결 복구** — 네트워크 단절·절전 중 오래된 상태를 표시하고 재개 후 heartbeat·출석·알림 동기화를 재개한다. LMS 장애와 서버 장애를 구분한다.

## 4. PC 업데이트

환경: D 실제 설치본·영구 QA 프로필·서명된 후보/테스트 업데이트 feed.
버전 정책·시점·실패 판정은 코드로, 실제 설치와 재시작은 대상 OS에서 확인합니다.

- [ ] **UPD-01 확인 상태** — 확인 중·최신·업데이트 있음·확인 실패를 구분하고 재시도할 수 있다. 초기 확인 중/실패에서는 현재 정책에 맞게 대시보드 진입을 제한한다.
- [ ] **UPD-02 선택 업데이트** — 패치·프리릴리스 업데이트는 계속 사용하거나 설치할 수 있고, 나중에 선택은 해당 버전에 적용된다. (정책은 코드 가능)
- [ ] **UPD-03 필수 업데이트** — 안정판 major/minor 상승 시 필수 안내가 대시보드 조작을 막고 업데이트 동작으로 포커스를 유지한다. (정책은 코드 가능)
- [ ] **UPD-04 설치** — 다운로드·검증·설치 진행을 표시하고 재시작 후 새 버전과 기존 설정을 확인한다.
- [ ] **UPD-05 실패·재시도** — 통신·서명·설치 실패를 성공으로 표시하지 않는다. 오류와 재시도 경로를 확인한다. (실패 조건은 코드 가능)
- [ ] **UPD-06 시작 전 설치** — 예약 업데이트를 안전한 시작 시점에 적용하고 사용자가 창을 열면 유예한다. 실패 후 무한 재시작하지 않는다. (시점은 코드 가능)

## 5. LMS·출석 조회

환경: 로그인된 D + 연결 P. Jungle Bell은 LMS 출석 상태를 읽습니다. 실제 출석 기록을 바꾸는
조작은 별도 허용이 필요하며, 날짜·시각 경계는 fixture나 코드 테스트로 재현할 수 있습니다.

- [ ] **ATT-01 LMS 로그인** — 미로그인에서 전용 Jungle Campus 창을 열어 로그인하면 조회를 시작한다. 로그인 도중 주기 갱신이 창을 방해하지 않는다.
- [ ] **ATT-02 LMS 창·세션** — 로그인 창을 닫아도 백그라운드 수집을 유지하고 앱 완전 종료·재실행 뒤 유효한 LMS 세션을 복원한다.
- [ ] **ATT-03 출석 동기화** — 학습 시작/종료 전후의 원본 상태가 PC 관측 → 서버 snapshot → PC/PWA 표시에 일치한다. 로컬 관측과 서버 동기화 대기를 구분한다.
- [ ] **ATT-04 수동·주기 갱신** — 새로고침과 주기 수집 후 확인 시각·표시가 갱신된다. 동일 관측을 반복해도 완료 상태나 알림이 중복 생성되지 않는다.
- [ ] **ATT-05 날짜 경계** — KST 출석 기준일과 자정을 넘는 학습 종료 구간을 구분하며 전날 snapshot을 오늘 출석으로 표시하지 않는다. (코드 가능)
- [ ] **ATT-06 기수·D-Day** — 자동 선택·수동 선택 후 적용한 기수의 출석·D-Day·진행률을 표시한다. 목록 없음·조회 실패·미적용 선택값도 구분한다.
- [ ] **ATT-07 수집 PC** — 수집 PC 이름·버전·LMS 상태·최근 확인과 온라인 여부를 표시하고 여러 PC를 구분한다.
- [ ] **ATT-08 만료·이상 응답** — LMS 세션 만료는 로그인 필요로, checker 오류·예상 밖 응답은 확인 불가로 표시하며 과거 값을 새 완료 상태로 만들지 않는다.
- [ ] **ATT-09 checker 복구** — 보고 누락·로드 실패에서 제한된 재시도 후 오류를 표시하고 정상화 후 수집을 재개한다. (코드 가능)
- [ ] **ATT-10 신선도 판단** — snapshot 신선도·PC 온라인 표시·알림 판단의 heartbeat 기준을 각각 적용하고 확인 불가를 미출석으로 단정하지 않는다. (코드 가능)

## 6. PC↔모바일 연결·계정 수명주기

환경: 로그인된 D + P, 해제·초기화가 허용된 QA 계정/기기. 원문 토큰 대신 별칭으로 구분합니다.

- [ ] **PAIR-01 연결 준비** — PC의 LMS·서버 인증 준비 상태에 따라 연결 코드 발급 또는 복구 안내를 표시한다.
- [ ] **PAIR-02 수동 연결** — PC의 10자리 코드 입력 → 모바일 요청 → 양쪽 기기명·확인 번호 대조 → PC 승인 후 개인 기능이 열린다.
- [ ] **PAIR-03 QR 설치 연결** — 미설치 모바일에서 QR을 열면 설치 안내로 이동한다. 설치 후 handoff가 유지되면 연결 요청, 없거나 만료됐으면 수동 코드 경로를 제공한다.
- [ ] **PAIR-04 QR 입력 처리** — challenge를 첫 렌더링 전 주소·history에서 제거하고 Web Storage/IndexedDB에 남기지 않는다. 비모바일 QR 진입은 claim 없이 홈으로 이동한다. (코드 가능)
- [ ] **PAIR-05 승인 대기** — 승인 전 개인 기능이 열리지 않는다. 대기 취소·코드 변경·만료·재발급과 앱 재시작 후 대기 상태 복원을 확인한다.
- [ ] **PAIR-06 입력 실패·복구** — 형식 오류·없는 코드·만료·통신 실패에서 원인과 재시도를 제공하고, 연결 성공 후 원래 개인 화면으로 돌아간다.
- [ ] **PAIR-07 기기 목록** — 연결 기기 0개·여러 개, 기기 이름·상태가 구분된다. 목록 조회 실패로 기존 연결을 삭제하지 않는다.
- [ ] **PAIR-08 개별 해제** — PC에서 특정 모바일을 해제하거나 PWA가 자체 해제하면 해당 기기의 새 개인 요청과 새 Push 대상이 비활성화되고 다른 기기는 유지된다.
- [ ] **PAIR-09 identity 초기화** — 확인 취소는 상태를 유지한다. 유효 credential의 서버 삭제 성공 후 로컬 상태·연결을 폐기하며 서버 실패 시 기존 identity를 보존한다.
- [ ] **PAIR-10 인증 복구** — PC credential 누락·만료·폐기와 PWA 세션 만료를 구분해 복구한다. credential 없는 재등록만으로 이전 모바일 연결까지 폐기됐다고 표시하지 않는다.
- [ ] **PAIR-11 세션 경계** — 단기 WebView 세션 재발급, 부모 credential rotate·폐기·만료, 모바일 세션 만료가 개인 API 권한에 반영된다. (코드 가능)
- [ ] **PAIR-12 계정 전환 경합** — 해제·identity 변경 도중 늦게 도착한 이전 응답과 캐시가 새 계정 화면에 섞이지 않는다. (코드 가능)

## 7. 세탁실·개인 세탁 알림

환경: 공개 조회 W/D/P, 개인 알림은 인증된 D/P와 동작 중 기기 세션. 경고·시점 재현은 통제된 데이터로 확인할 수 있습니다.

- [ ] **LAUN-01 공개 현황** — 구역·워시타워·세탁기/건조기 상태·잔여 시간·예상 종료와 남성/여성 시작 가능 수가 원본 및 홈 요약과 일치한다.
- [ ] **LAUN-02 상세·스크롤** — 기기 상세와 상태/구역 범례가 일치한다. 좁은 화면에서는 표 내부만 가로로 스크롤하고 페이지 전체는 넘치지 않는다.
- [ ] **LAUN-03 추정·완료 확인** — 관측 기반 잔여 시간의 추정 의미와 0분 이후 완료 확인 중 상태를 구분한다. 원천의 예약됨·오류·일시정지를 정상 사용 가능으로 세지 않는다.
- [ ] **LAUN-04 수집 실패·복구** — 지연·부분 수집·빈 응답·오프라인에서 마지막 정상값과 오류를 구분하고 신뢰할 수 없는 가능 수는 최신값으로 표시하지 않는다. 복구 후 새 관측을 표시한다. 최근 수집 성공과 원본 변화 미관측을 수집 지연으로 혼동하지 않으며, 수집 확인·현재 원본 내용의 첫 관측 시각과 저장된 응답의 유효성 경고를 구분한다. 서버 시각이 최대 60초 앞서도 정상 원본을 차단하지 않으며, 60초 초과 미래·만료된 응답·원본 지연은 계속 제한한다.
- [ ] **LAUN-05 위험 표시** — D/P의 최근 7일 위험 표시 켜기·끄기와 기기별 경고·상세가 일치하며 데이터 없는 상태를 구분한다.
- [ ] **LAUN-06 등록** — 인증 후 워시타워·동작 중 기기·알림 시점(완료 전/예상/확정)을 선택해 등록한다. 완료 전 분은 1~180만 허용한다. 미인증이면 개인 영역을 숨기고 출석 snapshot이 없으면 동기화 안내를 표시한다.
- [ ] **LAUN-07 중복·지연·취소** — 같은 활성 대상의 중복 등록을 막는다. 오래된 데이터는 신규 등록을 막되 기존 알림 취소는 가능하며 PC/PWA 목록에 반영된다.
- [ ] **LAUN-08 완료 전** — 잔여 시간이 1분 이상이고 지정 분 이내인 구간에서 해당 기기 작업 세션의 알림을 한 번 생성한다. (코드 가능)
- [ ] **LAUN-09 예상 완료** — 예상 완료 시점의 알림은 실제 관측 완료 알림과 구분된다. (코드 가능)
- [ ] **LAUN-10 확정 완료** — 같은 작업 세션의 실제 완료 관측 뒤 알림을 생성하며 취소한 알림은 만들지 않는다. (코드 가능)
- [ ] **LAUN-11 경고·재개** — 건조기 오류·일시정지를 한 번 경고하고 미해결 경고 뒤 idle을 정상 완료로 알리지 않는다. 재개 후 정상 완료 경로를 확인한다. (코드 가능)

## 8. 급식·기록

환경: W/D/P. 중식·석식·주간표·과거 기록이 있는 데이터와 미게시 상태를 준비합니다.

- [ ] **MEAL-01 오늘 급식** — 중식·석식의 날짜·메뉴·사진이 원본 및 홈 요약과 일치한다.
- [ ] **MEAL-02 주간표** — 해당 주의 식단표 이미지·내용을 열고 다른 주 게시물과 섞이지 않는지 확인한다.
- [ ] **MEAL-03 기록 탐색** — 달력 월 이동·날짜 선택 시 해당 날짜 식사와 주간표를 함께 갱신한다. 기록 없는 날짜·월은 빈 상태를 표시한다.
- [ ] **MEAL-04 이미지·원문** — 이미지 보기와 원문 열기가 동작한다. 사진 없음·이미지 로드 실패·게시물 미등록 상태를 구분한다.
- [ ] **MEAL-05 갱신·실패** — 새로고침 후 최신 게시물·확인 시각을 표시한다. 수집 실패 시 마지막 정상 식단과 오류를 표시하고 복구한다.
- [ ] **MEAL-06 자산 계약** — 급식 이미지의 origin·해시·확장자 검증과 없는 이미지 요청 처리가 맞고 주간표 연결이 정확하다. (코드 가능)

## 9. 알림 설정·알림함·실제 전달

환경: 인증된 D/P, API·Worker, OS 알림 권한. P는 HTTPS·Service Worker·Push가 필요합니다.
요청 접수·알림함 생성·provider 전달·OS 실제 표시를 별도 결과로 구분합니다.

- [ ] **NOTI-01 전달 준비** — 권한·로컬 구독·서버 등록·테스트 발송·실제 도착 상태를 각각 표시하고, 준비 안 된 단계의 복구 안내가 맞다.
- [ ] **NOTI-02 나중에·재진입** — 알림 점검을 건너뛰어도 앱을 사용할 수 있고 이후 다시 점검·테스트할 수 있다.
- [ ] **NOTI-03 PC 테스트** — 테스트 요청 후 알림함 항목과 실제 OS 알림을 각각 확인한다. 표시 실패는 성공과 구분하고 OS 설정 열기·재시도를 제공한다.
- [ ] **NOTI-04 PWA 테스트** — 설치 PWA에서 권한 허용·구독·서버 등록 후 실제 Push 도착을 확인한다. 도착/미도착 선택과 재전송 흐름이 맞다.
- [ ] **NOTI-05 거부·재등록·끄기** — 권한 거부·구독 유실·공개키/SW 준비 실패에서 복구할 수 있다. 재등록과 알림 끄기의 실제 구독/등록 상태가 화면과 일치한다.
- [ ] **NOTI-06 백그라운드·대상별 전달** — PC 창을 숨기거나 PWA를 백그라운드로 보내도 유효한 알림을 받는다. 활성 대상별 전달을 확인하고 해제된 대상에는 새 전달을 만들지 않는다.
- [ ] **NOTI-07 클릭·닫기** — OS 알림 클릭 시 관련 출석·급식·세탁 화면을 연다. D는 읽음을 반영하고 P는 기존 창 복귀·화면 이동만 한다. P의 읽음은 앱 알림함에서 처리한다. 단순 알림 닫기는 화면을 열지 않는다.
- [ ] **NOTI-08 패널** — 알림 패널을 열어도 배경 화면을 유지한다. 닫기·Escape·포커스 복귀, 새/지난 알림 탭, 알림 대상 이동이 동작한다.
- [ ] **NOTI-09 읽음·조회 실패** — 개별/전체 읽음 후 배지 수와 탭이 갱신되고 0이면 배지가 숨겨진다. 빈 목록과 조회 실패를 구분하고 재시도할 수 있다.
- [ ] **NOTI-10 처리·중복** — 같은 이벤트 재계획·poll 재시도·앱/Worker 재시작에서 중복 알림을 만들지 않고, PC는 표시 성공/실패를 ack한다. (코드 가능, 실제 표시 중복은 실행 확인)
- [ ] **NOTI-11 재시도·만료** — Worker/provider 장애 뒤 유효한 pending만 재처리한다. backoff·상한·delivery lease, 만료 알림/비활성 세션 제외, `404/410` 구독 정리가 맞다. (코드 가능)
- [ ] **NOTI-12 연속 테스트 요청** — 테스트 요청 제한 시 안내하고 다시 시도할 수 있다. 요청 접수 `202`나 제한 `429`를 실제 도착 성공으로 처리하지 않는다. (제한은 코드 가능)

## 10. 출석·급식 알림 정책

환경: 인증된 D/P의 설정 화면. 시간·출석 상태·게시물 조건은 코드 테스트/fixture로 재현하고,
종류별 실제 전달·클릭은 위 알림 전달 항목과 함께 확인합니다.

- [ ] **PREF-01 출석 설정** — 전체/학습 시작/학습 종료, 시각·간격·일요일 제외·이번 출석일 건너뛰기를 저장하고 PC/PWA에서 같은 값으로 재조회한다.
- [ ] **PREF-02 급식 설정** — 전체/중식/석식 토글의 수정·저장·실패 안내를 확인하고 PC/PWA에서 같은 값으로 재조회한다.
- [ ] **PREF-03 시작·종료 알림** — 최신 출석의 미완료 단계만 설정 시간·간격에 맞춰 알리고 완료 후 및 알림 구간 종료 후 중단한다. (코드 가능)
- [ ] **PREF-04 제외 정책** — 전체/개별 OFF, 일요일 제외, 해당 출석일 건너뛰기가 적용되고 다음 출석일에는 건너뛰기가 해제된다. (코드 가능)
- [ ] **PREF-05 확인 불가** — PC 오프라인·LMS 만료·snapshot 지연은 완료/미완료를 단정하지 않고 제한된 안내 슬롯만 사용하며 상태 변경·재시작으로 중복하지 않는다. (코드 가능)
- [ ] **PREF-06 급식 알림** — 새 중식·석식 게시물은 해당 설정이 켜진 계정에 한 번 알리고 OFF인 종류·전체 OFF에는 만들지 않는다. (코드 가능)

## 11. 앱 상태·개인정보·사용 통계

환경: W/D/P. 개인 상태·통계 설정은 QA 계정이 필요합니다. 통계 상세 조건은
작업 저장소의 `docs/process-usage-metrics-qa.md`를 참고합니다.

- [ ] **INFO-01 PC 상태** — LMS·PC 서버 인증·출석 동기화·연결 모바일·OS 알림·업데이트 상태와 경고 수가 일치하고 관련 복구 화면으로 이동한다.
- [ ] **INFO-02 PWA 상태** — 세션 만료·권한·구독·서버 등록·Service Worker·최근 테스트 상태를 구분하고 복구 링크가 맞다.
- [ ] **INFO-03 플랫폼별 설정** — W/P에서 PC 전용 서비스 설정은 안내로 표시하고 지원하지 않는 네이티브 동작을 실행하지 않는다.
- [ ] **INFO-04 개인정보 안내** — `/privacy`의 수집 항목·보관·선택권 안내와 홈 복귀가 동작한다. 익명 통계 선택의 저장·재조회·실패 안내를 확인한다.
- [ ] **INFO-05 계정 통계 선택** — 설정 파일·identity가 없는 완전 신규 PC만 기본 ON이며 선택 복원 불가/null·OFF는 수집하지 않는다. PC 선택은 서버 확인 후 연결 PWA에도 적용하고 동기화 대기를 구분한다. 익명 웹 opt-out은 별도로 유지한다. (수집 판정은 코드 가능)
- [ ] **INFO-06 전송 범위** — 자동 UI 열림은 production/release 전송 조건을 따르고 중복·재시도·동의 철회를 처리한다. 서버 기능 통계는 ON 계정이면 개발 앱 요청도 기록한다. LMS 정보·출석 내용·세션 원문은 payload나 로그에 포함되지 않는다. (코드 가능)
- [ ] **INFO-07 집계·보관** — API `204`와 실제 집계 반영을 구분한다. 비식별 집계·보관기간·삭제 작업이 계약과 맞으며 OFF가 과거 데이터 즉시 삭제로 안내되지 않는다. (코드 가능)

## 12. 서버·인증·배포 계약

환경: 해당 SHA의 코드 검사, 필요 시 격리된 API·Worker·DB. 기존 검사 결과를 근거로 묶어
기록합니다. 운영 장애를 만들거나 매 항목마다 수동으로 인증 경계를 공격할 필요는 없습니다.

- [ ] **SYS-01 코드 검사** — 후보 SHA의 frontend/desktop/server 필수 검사와 빌드 결과를 확인한다. 서버는 Docker 환경에서 통합 테스트까지 통과해야 하며, 단위 테스트만 실행한 결과로 대체하지 않는다.
- [ ] **SYS-02 상태 API** — 공개 health·수집 상태와 내부 readiness가 각각 서비스·수집·DB 상태를 구분한다. 내부 관리 endpoint의 공개 범위가 배포 설정과 맞다.
- [ ] **SYS-03 수집·작업 복구** — 세탁·급식 수집 실패나 알림 작업 실패가 API·다른 작업을 중단시키지 않고 재개 후 새 관측·대기 전달을 처리한다. (코드 가능)
- [ ] **SYS-04 공개/개인 권한** — 공개 조회와 개인 API, PC·WebView·모바일 세션의 권한이 분리되며 `401/403`과 허용된 Origin 처리가 계약에 맞다. (코드 가능)
- [ ] **SYS-05 자격 증명 보관** — LMS 인증 정보·원문은 서버 저장/전송 대상이 아니고 PC 장기 credential은 WebView에 제공되지 않는다. 쿠키 속성과 로그 마스킹을 확인한다. (코드 가능)
- [ ] **SYS-06 버전·산출물** — 서버·frontend·Tauri 버전과 후보 태그/SHA가 일치한다. 배포 대상별 설치본·업데이트 메타데이터·서명과 연결된 다운로드를 확인한다.
- [ ] **SYS-07 이번 릴리스의 이전 작업** — 스키마·설정·세션·데이터 이전이 있으면 지원 조합과 복구 경로를 확인한다. 없으면 이유를 적고 비해당으로 둔다.

기존 검사 진입점: `CONTRIBUTING.md`, `frontend/package.json`, `desktop/src/`의 Rust 테스트,
`server/{core,api,worker}/src/test/`. 주요 근거는 frontend의 routing·platform·PWA 계약 검사,
서버의 `PairingServiceTest`, `AccountServiceTest`, `AutomationEngineTest`, `NotificationServiceTest`,
`JdbcStoreIntegrationTest`, `SecurityFilterChainIntegrationTest`, `WebPushSenderTest` 등입니다.
각 검사의 실제 단언 범위만 근거로 삼고, 같은 기능 이름의 테스트 하나로 전체 항목을 통과시키지 않습니다.
`server/tools/smoke-api.sh`는 등록·heartbeat·identity 삭제를 수행하므로 계정 범위를 먼저 준비합니다.
웹 직접 조작은 `docs/guide-playwright-qa.md`의 headless Chromium 지속 세션을 사용합니다.
