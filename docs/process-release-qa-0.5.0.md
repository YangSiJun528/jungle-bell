# Jungle Bell 0.5.0 릴리스 QA 체크리스트

## 목적

Jungle Bell 0.5.0 리뉴얼 버전의 출석 상태 수집·표시, 플랫폼별 기능 분리, 알림 전달과 핵심 생활 기능을 출시 전에 검증한다.

0.5.0은 이전 버전의 사용자 데이터, 인증 정보, 세션, 연결 상태와 하위 호환성을 보장하지 않는다. 공개 세탁·급식 기록 외 데이터 이전은 검증 대상이 아니다.

> Jungle Bell은 자동 출석을 제공하지 않는다. 이 문서에서 "출석 확인"은 PC 앱이 Jungle Campus의 출석 상태를 읽고 Jungle Bell에 동기화·표시하는 동작을 뜻한다.

## 사용 방법

- `[ ]`: 미실행
- `[x]`: 통과
- 실패한 항목은 체크하지 않고 문장 끝에 `❌ FAIL — 이슈 링크`를 추가한다.
- 차단된 항목은 체크하지 않고 문장 끝에 `⛔ BLOCKED — 사유`를 추가한다.
- `P0` 실패 또는 차단이 하나라도 있으면 출시하지 않는다.
- `P1` 실패는 영향 범위와 우회 방법을 확인한 뒤 출시 여부를 별도로 결정한다.
- 각 항목은 실제 운영과 동일한 API·Worker·Push 구성에서 검증한다.

## 1. 0.5.0 전환과 비호환 변경

- [ ] **REN-001 [P0] 새 PC 설치** — 0.5.0을 사용자 데이터가 없는 PC에 설치하면 앱이 정상 실행되고 새 PC identity를 등록한다.
- [ ] **REN-002 [P0] 이전 PC 인증 정보** — 0.5.0이 이전 버전의 인증 정보나 서버 세션을 정상 연결로 오인하지 않고 재등록·복구 안내를 표시한다.
- [ ] **REN-003 [P0] 이전 PWA 세션** — 이전 버전 PWA 세션으로 개인 API에 접근할 수 없고 PC 재연결 안내가 표시된다.
- [ ] **REN-004 [P0] 재연결** — 0.5.0 PC에서 새 연결 코드를 만들고 PWA를 다시 연결하면 개인 기능이 복구된다.
- [ ] **REN-005 [P1] 레거시 경로** — 과거 `/pair`, `/app` 경로가 기존 화면으로 동작하지 않으며 현재 진입 경로로 안전하게 안내되거나 홈으로 이동한다.
- [ ] **REN-006 [P0] 레거시 API** — 이전 `/v1` API와 내부 SQL/object gateway가 외부에 노출되지 않는다.
- [ ] **REN-007 [P1] 공개 데이터 유지** — 전환 후 공개 세탁·급식 기록과 이미지가 정상 조회된다.
- [ ] **REN-008 [P1] 버전 표시** — PC 연결 정보·출석 수집 기기에 앱 버전 `0.5.0`이 기록·표시된다.

## 2. 퍼블릭 웹

- [ ] **WEB-001 [P0] 최초 진입** — 공식 URL을 시크릿 창에서 열면 인증 없이 홈 화면이 로드된다.
- [ ] **WEB-002 [P0] 공개 범위** — 홈에서 공개 세탁 요약과 오늘 식단만 확인할 수 있다.
- [ ] **WEB-003 [P0] 출석 제한** — 출석 화면에 개인 출석 데이터 대신 PC 앱 또는 설치형 PWA가 필요하다는 안내가 표시된다.
- [ ] **WEB-004 [P0] 개인 API 차단** — 일반 웹이 `/api/me/*`를 호출하거나 개인 응답을 캐시하지 않는다.
- [ ] **WEB-005 [P0] 알림 제한** — 알림 화면에서 개인 알림함·테스트 알림 대신 설치/연결 안내를 제공한다.
- [ ] **WEB-006 [P0] 연결 기능 제한** — PC 연결 코드 입력·승인·모바일 관리 기능이 일반 웹 surface에 노출되지 않는다.
- [ ] **WEB-007 [P1] 설치 안내** — 지원 브라우저에서 PWA 설치 안내가 열리고 수락·취소가 모두 정상 처리된다.
- [ ] **WEB-008 [P1] 새로고침** — 홈·세탁·급식의 새로고침이 중복 실행되지 않고 최신 데이터를 표시한다.
- [ ] **WEB-009 [P1] 수집 실패** — 공개 데이터 수집 실패 시 마지막 정상 데이터와 실패 안내를 함께 표시한다.
- [ ] **WEB-010 [P1] 직접 URL** — `/#/home`, `/#/attendance`, `/#/laundry`, `/#/meals` 직접 진입과 새로고침이 동작한다.
- [ ] **WEB-011 [P1] 잘못된 경로** — 허용 목록에 없는 hash 경로는 홈으로 안전하게 이동한다.
- [ ] **WEB-012 [P1] 모바일 레이아웃** — 작은 화면에서 하단 탐색, 알림·설정 진입, 콘텐츠 스크롤에 잘림이나 겹침이 없다.

## 3. PC 데스크탑

### 설치와 계정 상태

- [ ] **PC-001 [P0] 최초 실행** — 새 설치에서 대시보드와 트레이 아이콘이 뜨고 서버 PC 등록이 완료된다.
- [ ] **PC-002 [P0] LMS 미로그인** — Jungle Campus 미로그인 상태를 `로그인 필요`로 표시하고 로그인 버튼이 전용 WebView를 연다.
- [ ] **PC-003 [P0] LMS 로그인** — 전용 WebView 로그인 후 대시보드가 로그인 상태를 감지하고 출석 조회를 시작한다.
- [ ] **PC-004 [P0] 자격 증명 경계** — LMS cookie·token·Google SSO credential이 서버 요청, 로그, 개발자 도구에 노출되지 않는다.
- [ ] **PC-005 [P0] 서버 세션** — 대시보드가 장기 PC credential 대신 단기 WebView session으로 `/api/me/*`를 호출한다.
- [ ] **PC-006 [P0] 세션 복구** — PC credential 누락·만료·폐기 상태에서 연결된 것처럼 보이지 않고 복구 또는 재등록 절차를 제공한다.
- [ ] **PC-007 [P1] 재실행 유지** — 앱 종료 후 재실행해도 유효한 PC identity와 설정이 유지된다.

### 출석 수집과 트레이

- [ ] **PC-008 [P0] 자동 수집** — 로그인된 PC가 약 5분 간격으로 출석 상태와 heartbeat를 서버에 동기화한다.
- [ ] **PC-009 [P0] 수동 갱신** — 출석 화면의 새로고침이 즉시 LMS 상태 확인과 서버 snapshot 갱신을 수행한다.
- [ ] **PC-010 [P0] 학습 시작 상태** — 학습 시작 완료·미완료가 Jungle Campus 실제 값과 동일하게 표시된다.
- [ ] **PC-011 [P0] 학습 종료 상태** — 학습 종료 완료·미완료가 Jungle Campus 실제 값과 동일하게 표시된다.
- [ ] **PC-012 [P0] 트레이 상태** — 확인 중/불가, 출석 가능, 학습 중, 완료, 로그인 필요 상태에 맞는 트레이 아이콘이 표시된다.
- [ ] **PC-013 [P1] 테마 전환** — 밝은·어두운 OS 테마에서 트레이 아이콘과 대시보드 상태가 식별 가능하다.
- [ ] **PC-014 [P0] 절전·종료** — PC 종료 또는 절전 중 서버가 출석을 최신으로 추측하지 않고 오래된 상태로 처리한다.
- [ ] **PC-015 [P0] 네트워크 복구** — 네트워크 단절 중 오류 상태를 표시하고 연결 복구 후 자동으로 heartbeat·출석 동기화를 재개한다.
- [ ] **PC-016 [P1] 다중 기기 표시** — 출석 화면의 수집 PC 목록에 기기명, 마지막 확인, LMS 상태, 앱 버전이 정확히 표시된다.
- [ ] **PC-017 [P1] D-Day** — 선택된 기수의 시작·종료일을 기준으로 D-Day와 진행률이 정확하다.

### PC 전용 설정

- [ ] **PC-018 [P1] 자동 시작** — 설정을 켜면 OS 로그인 후 앱이 백그라운드 실행되고 끄면 실행되지 않는다.
- [ ] **PC-019 [P1] 자동 업데이트** — 자동 업데이트 설정과 해제 확인 대화상자가 동작하며 서명된 업데이트만 적용한다.
- [ ] **PC-020 [P1] 사용 통계** — 사용 통계를 끄면 전송하지 않고, 켜도 출석·식단 내용이나 LMS 계정 정보는 포함하지 않는다.
- [ ] **PC-021 [P1] 디버그 모드** — 확인 대화상자 후 상세 로그가 켜지고 다시 끄면 정상 수준으로 돌아온다.
- [ ] **PC-022 [P1] 로그 폴더** — 로그 폴더 열기가 Jungle Bell 전용 디렉터리를 연다.
- [ ] **PC-023 [P1] 기수 선택** — 자동 선택과 수동 기수 선택이 저장되고 출석·D-Day에 반영된다.
- [ ] **PC-024 [P1] identity 초기화** — 경고 확인 후 PC identity를 초기화하면 기존 모바일 세션이 더 이상 개인 데이터에 접근하지 못한다.

## 4. 설치형 PWA

### 설치와 연결

- [ ] **PWA-001 [P0] 설치형 판정** — 홈 화면/앱으로 설치해 standalone으로 실행할 때만 PWA 개인 기능이 활성화된다.
- [ ] **PWA-002 [P0] 브라우저 탭과 분리** — 같은 URL을 일반 브라우저 탭으로 열면 설치형 PWA session으로 오인하지 않는다.
- [ ] **PWA-003 [P0] 수동 코드 연결** — PC가 만든 10자리 코드를 입력하고 PC 승인 후 연결이 완료된다.
- [ ] **PWA-004 [P0] QR 연결** — PC의 QR을 열어 claim하고 PC 확인 코드·기기명이 일치한 상태에서 승인된다.
- [ ] **PWA-005 [P0] 승인 전 차단** — PC 승인 전에는 모바일 session이 발급되지 않고 개인 데이터를 조회할 수 없다.
- [ ] **PWA-006 [P0] 코드 만료** — 2분이 지난 연결 코드는 거부되고 새 코드 발급 안내가 표시된다.
- [ ] **PWA-007 [P1] 잘못된 코드** — 형식이 잘못되거나 존재하지 않는 코드에서 구체적인 실패 안내가 표시되고 재시도할 수 있다.
- [ ] **PWA-008 [P0] 세션 저장** — 연결 완료 후 Strict HttpOnly cookie로 session이 유지되고 JavaScript·서비스 워커에서 원문을 읽을 수 없다.
- [ ] **PWA-009 [P0] 앱 재실행** — PWA를 완전히 종료했다가 다시 실행해도 유효한 session이면 연결 상태와 개인 기능이 복구된다.
- [ ] **PWA-010 [P0] 연결 해제** — PC에서 모바일을 해제하면 해당 PWA의 개인 API 접근과 Push 대상이 즉시 비활성화된다.
- [ ] **PWA-011 [P1] 자체 연결 해제** — PWA에서 현재 session을 해제하면 공개 기능만 남고 재연결 안내가 표시된다.
- [ ] **PWA-012 [P1] 다중 모바일** — 두 대 이상의 PWA를 연결해 각 기기명이 구분되고 개별 해제가 가능하다.

### 개인 기능

- [ ] **PWA-013 [P0] 출석 조회** — PC가 동기화한 학습 시작·학습 종료 상태, 기준일, 수집 PC 상태가 표시된다.
- [ ] **PWA-014 [P0] LMS 직접 조회 금지** — PWA가 Jungle Campus에 로그인하거나 LMS를 직접 호출하지 않는다.
- [ ] **PWA-015 [P0] PC 오프라인** — PC heartbeat가 오래되면 최신 상태로 오인하지 않고 확인 불가·오래됨을 표시한다.
- [ ] **PWA-016 [P1] 설정 공유** — PWA에서 저장한 출석·급식 알림 설정이 PC에도 동일하게 표시된다.
- [ ] **PWA-017 [P1] 세탁 알림 공유** — PWA에서 추가·삭제한 세탁 watch가 PC에도 반영된다.
- [ ] **PWA-018 [P1] 오프라인 재진입** — 네트워크가 없는 상태에서 민감한 이전 응답을 잘못된 계정에 노출하지 않고 복구 후 최신 상태를 조회한다.

## 5. 출석 확인 종단 간 검증

- [ ] **ATT-001 [P0] 학습 시작 전** — Jungle Campus에서 학습 시작 전 상태를 만든 뒤 PC 수집 → 서버 snapshot → PC/PWA 표시가 모두 미완료로 일치한다.
- [ ] **ATT-002 [P0] 학습 시작 후** — Jungle Campus에서 직접 학습 시작한 뒤 수동 갱신하여 PC/PWA가 완료로 바뀐다.
- [ ] **ATT-003 [P0] 학습 종료 전** — 학습 종료 가능 시간의 미완료 상태가 PC/PWA에 동일하게 표시된다.
- [ ] **ATT-004 [P0] 학습 종료 후** — Jungle Campus에서 직접 학습 종료한 뒤 PC/PWA가 완료로 바뀐다.
- [ ] **ATT-005 [P0] 날짜 경계** — Asia/Seoul 자정 전후에 전날 snapshot이 당일 출석으로 표시되지 않는다.
- [ ] **ATT-006 [P0] LMS 세션 만료** — LMS session 만료 시 로그인 필요 상태로 전환되고 과거 출석을 새 상태로 덮어쓰지 않는다.
- [ ] **ATT-007 [P0] LMS 응답 오류** — checker 오류나 예상하지 못한 LMS 응답에서 잘못된 완료 상태를 생성하지 않는다.
- [ ] **ATT-008 [P1] 빈 기수 목록** — LMS 로그인 전 기수 목록이 비어 있어도 앱이 중단되지 않고 안내를 표시한다.
- [ ] **ATT-009 [P1] 기수 변경** — 수동으로 기수를 변경하면 해당 기수의 출석·D-Day가 다시 계산된다.
- [ ] **ATT-010 [P1] 반복 갱신** — 같은 출석 상태를 여러 번 수집해도 불필요한 상태 변경이나 중복 알림이 생기지 않는다.

## 6. 알림 종단 간 검증

### 공통 전달 경로

- [ ] **NOTI-001 [P0] PC 테스트 알림** — PC에서 테스트 알림을 보내면 API 응답 후 실제 OS 알림과 PC 알림함 항목을 모두 확인할 수 있다.
- [ ] **NOTI-002 [P0] PWA 테스트 Push** — 설치형 PWA에서 Push를 연결하고 테스트 알림을 보내면 실제 OS Push와 PWA 알림함 항목을 모두 확인할 수 있다.
- [ ] **NOTI-003 [P0] 전체 대상 fan-out** — 하나의 테스트 notification이 현재 PC와 연결된 모든 활성 PWA에 각각 한 번씩 전달된다.
- [ ] **NOTI-004 [P0] API 202 의미** — 테스트 endpoint의 `202`만으로 통과 처리하지 않고 Worker 처리와 실제 단말 표시까지 확인한다.
- [ ] **NOTI-005 [P0] 미연결 기기 제외** — 해제·만료된 모바일 session과 비활성 Push 구독에는 알림이 전달되지 않는다.
- [ ] **NOTI-006 [P0] 중복 방지** — poll 재시도, 앱 재실행, Worker 재시작 후에도 같은 delivery가 단말에 중복 표시되지 않는다.
- [ ] **NOTI-007 [P0] PC ack** — PC가 표시 성공/실패 결과를 ack하고 이미 처리한 delivery를 계속 poll하지 않는다.
- [ ] **NOTI-008 [P0] Push 재시도** — 일시적 Push provider 실패 시 backoff 후 재시도하고 다른 알림 계획을 막지 않는다.
- [ ] **NOTI-009 [P0] 만료 구독 정리** — Push provider가 `404` 또는 `410`을 반환하면 해당 구독을 폐기한다.
- [ ] **NOTI-010 [P1] 권한 거부** — OS 또는 브라우저 알림 권한을 거부하면 명확한 오류와 복구 안내가 표시된다.
- [ ] **NOTI-011 [P1] 앱 비활성 상태** — PC 창이 닫혀 있거나 PWA가 백그라운드여도 지원 환경에서 알림이 표시된다.
- [ ] **NOTI-012 [P1] 알림 클릭** — 알림 클릭 시 관련 출석·세탁·식단 화면으로 이동하고 읽음 상태가 갱신된다.
- [ ] **NOTI-013 [P1] 읽음 처리** — 새 알림을 본 알림으로 처리하면 읽지 않은 개수와 새/지난 알림 탭이 즉시 갱신된다.
- [ ] **NOTI-014 [P1] 최근 목록 실패** — 최신 알림 조회 실패 시 마지막 목록을 유지하고 새로고침 안내를 표시한다.

### 출석 알림

- [ ] **NOTI-015 [P0] 학습 시작 미완료** — 학습 시작 미완료 상태에서 설정한 시작 시각과 간격에 맞춰 PC/PWA에 알림이 전달된다.
- [ ] **NOTI-016 [P0] 학습 시작 완료 후 중단** — 학습 시작 완료 후 같은 날 학습 시작 알림이 추가로 계획되지 않는다.
- [ ] **NOTI-017 [P0] 학습 종료 미완료** — 학습 종료 미완료 상태에서 설정한 간격으로 알림이 전달되고 종료 시각 이후에는 중단된다.
- [ ] **NOTI-018 [P0] 학습 종료 완료 후 중단** — 학습 종료 완료 후 같은 날 학습 종료 알림이 추가로 계획되지 않는다.
- [ ] **NOTI-019 [P0] 전체 끄기** — `출석 알림 사용`을 끄면 학습 시작·학습 종료 delivery가 생성되지 않는다.
- [ ] **NOTI-020 [P1] 학습 시작/종료 개별 끄기** — 개별 토글을 끈 단계만 알림이 생성되지 않는다.
- [ ] **NOTI-021 [P1] 일요일 제외** — 일요일 제외가 켜져 있으면 일요일 출석 알림이 계획되지 않는다.
- [ ] **NOTI-022 [P1] 하루 건너뛰기** — 이번 출석일 건너뛰기는 해당 기준일에만 적용되고 다음 출석일에는 자동 해제된다.
- [ ] **NOTI-023 [P0] 오래된 snapshot** — 출석 snapshot이 오래되거나 PC 상태를 확인할 수 없으면 완료/미완료를 추측한 알림을 보내지 않는다.

### 급식·세탁 알림

- [ ] **NOTI-024 [P1] 중식 알림** — 급식 알림과 중식이 켜진 계정에 새 중식 게시물 알림이 한 번만 전달된다.
- [ ] **NOTI-025 [P1] 석식 알림** — 급식 알림과 석식이 켜진 계정에 새 석식 게시물 알림이 한 번만 전달된다.
- [ ] **NOTI-026 [P1] 급식 선택 제외** — 중식 또는 석식을 끄면 해당 종류 알림이 생성되지 않으며 조식 알림은 존재하지 않는다.
- [ ] **NOTI-027 [P1] 세탁 10분 전** — 동작 중인 기기 watch는 예상 종료 10분 전에 한 번 알린다.
- [ ] **NOTI-028 [P1] 세탁 완료** — 완료 상태가 실제 수집값으로 확인된 뒤 완료 알림을 한 번 보낸다.
- [ ] **NOTI-029 [P1] 사용 가능** — 대기 watch는 대상 기기가 사용 가능해졌을 때 한 번 알린다.
- [ ] **NOTI-030 [P1] 추정값 보호** — 남은 시간이 0분이어도 실제 완료가 확인되기 전에는 완료 알림을 확정하지 않는다.
- [ ] **NOTI-031 [P1] watch 취소** — 세탁 watch를 삭제한 뒤에는 해당 조건의 알림이 생성되지 않는다.

## 7. 세탁실

- [ ] **LAUN-001 [P0] 최신 상태** — 세탁기·건조기의 사용 가능, 동작 중, 남은 시간, 예상 종료 시각이 source와 일치한다.
- [ ] **LAUN-002 [P1] 구역 표시** — 남성·여성·공용 zone 색상과 범례가 모든 화면에서 동일하다.
- [ ] **LAUN-003 [P1] 시작 가능 횟수** — 홈과 세탁실의 남성·여성 시작 가능 횟수가 기기 상태에서 정확히 계산된다.
- [ ] **LAUN-004 [P1] 추정 표시** — 마지막 관측값으로 계산한 남은 시간에는 `추정` 의미가 구분된다.
- [ ] **LAUN-005 [P1] 완료 확인 중** — 추정 시간이 0분이 된 뒤 실제 완료 수집 전에는 `완료 확인 중`으로 표시된다.
- [ ] **LAUN-006 [P1] 오래된 데이터** — freshness 기준을 넘긴 상태는 최신처럼 보이지 않고 확인 중/오래됨 안내를 표시한다.
- [ ] **LAUN-007 [P1] 수집 실패** — 수집 실패 시 마지막 정상 snapshot을 유지하고 실패 안내를 표시한다.
- [ ] **LAUN-008 [P1] 빈 상태** — 기기 목록이 비어 있어도 화면이 깨지지 않고 빈 상태 안내를 표시한다.
- [ ] **LAUN-009 [P1] watch 추가** — 동작 중 기기와 사용 대기 기기에 맞는 세탁 알림을 추가할 수 있다.
- [ ] **LAUN-010 [P1] 중복 watch** — 같은 활성 대상의 중복 watch 추가가 차단된다.
- [ ] **LAUN-011 [P1] watch 삭제** — 알림을 삭제하면 PC와 PWA 목록에 즉시 반영된다.

## 8. 급식

- [ ] **MEAL-001 [P0] 오늘 식단** — 당일 중식·석식 게시물이 날짜와 종류에 맞게 표시된다.
- [ ] **MEAL-002 [P1] 이번 주 급식표** — 현재 주차의 주간 식단 이미지·내용이 표시되고 다른 주차 게시물과 섞이지 않는다.
- [ ] **MEAL-003 [P1] 월별 기록** — 달력에서 날짜를 선택하면 해당 월·날짜의 과거 식단이 표시된다.
- [ ] **MEAL-004 [P1] 이미지 자산** — SHA 기반 급식 이미지 URL이 정상 로드되고 잘못된 확장자·해시 요청은 안전하게 실패한다.
- [ ] **MEAL-005 [P1] 게시물 없음** — 오늘 또는 이번 주 식단이 없을 때 빈 상태 안내가 표시된다.
- [ ] **MEAL-006 [P1] 수집 실패** — 수집 실패 시 마지막 정상 식단을 유지하고 실패 안내를 표시한다.
- [ ] **MEAL-007 [P1] 수동 새로고침** — 중복 요청 없이 최신 식단을 다시 조회하고 갱신 시각을 표시한다.
- [ ] **MEAL-008 [P1] 알림 설정 저장** — 급식 전체·중식·석식 토글이 저장되고 PC/PWA에서 동일하게 조회된다.

## 9. 연결과 세션 관리

- [ ] **CONN-001 [P0] PC 연결 코드 생성** — LMS 로그인과 서버 session이 준비된 PC만 QR·10자리 코드를 생성한다.
- [ ] **CONN-002 [P0] 확인 코드 대조** — PC 승인 화면의 기기명과 확인 코드가 PWA와 일치한다.
- [ ] **CONN-003 [P0] 권한 분리** — pairing 승인과 모바일 session 관리는 Tauri WebView session에서만 허용된다.
- [ ] **CONN-004 [P0] origin 검사** — release Tauri origin과 지정된 dev origin 외 요청은 WebView session을 발급받지 못한다.
- [ ] **CONN-005 [P0] PC credential 만료** — 90일 절대 만료 및 만료 전 rotate가 정책대로 동작한다.
- [ ] **CONN-006 [P0] WebView session 만료** — 7분 절대 만료 후 자동 재발급 또는 인증 복구 흐름이 동작한다.
- [ ] **CONN-007 [P0] 부모 session 폐기** — 부모 PC session의 rotate·폐기·만료 후 기존 WebView session이 즉시 무효화된다.
- [ ] **CONN-008 [P1] 모바일 목록 빈 상태** — 연결된 모바일이 0개인 경우 오류가 아닌 정상 빈 목록으로 표시된다.
- [ ] **CONN-009 [P1] 연결 상태 조회 실패** — 네트워크 오류 시 기존 연결을 임의로 삭제하지 않고 재시도 안내를 제공한다.

## 10. 공통 UI·오류·보안

- [ ] **COMMON-001 [P0] 플랫폼 기능 분리** — 퍼블릭 웹, PC, PWA에서 지원하지 않는 capability 호출이 발생하지 않는다.
- [ ] **COMMON-002 [P0] 인증 실패 처리** — `401/403`에서 다른 사용자의 캐시 데이터를 남기지 않고 연결 또는 로그인 안내로 전환한다.
- [ ] **COMMON-003 [P0] 비밀정보 로그 금지** — 서버·PC·브라우저 로그에 LMS cookie/token, `jbd_`, `jbui_`, 모바일 session 원문이 없다.
- [ ] **COMMON-004 [P1] 로딩 상태** — 홈·출석·세탁·급식·알림·설정에서 요청 중임을 알 수 있고 중복 조작이 차단된다.
- [ ] **COMMON-005 [P1] 오류 상태** — 네트워크·서버 오류 시 사용자 행동이 가능한 오류 메시지와 재시도 버튼이 표시된다.
- [ ] **COMMON-006 [P1] 빈 상태** — 데이터·알림·연결 기기가 없을 때 빈 화면 대신 의미 있는 안내를 표시한다.
- [ ] **COMMON-007 [P1] 반응형 레이아웃** — 지원 화면 크기에서 카드, 표식, 버튼, 대화상자, 알림 패널이 잘리지 않는다.
- [ ] **COMMON-008 [P1] 키보드 접근** — 주요 탐색, 대화상자, 탭, 토글, 선택 상자를 키보드로 조작할 수 있고 포커스가 보인다.
- [ ] **COMMON-009 [P1] 스크린 리더 이름** — 아이콘 버튼, 알림 개수, 현재 메뉴, 상태 변화에 의미 있는 접근성 이름이 있다.
- [ ] **COMMON-010 [P1] 밝은·어두운 테마** — 텍스트, 상태색, 경고, 비활성 컨트롤의 대비가 충분하다.
- [ ] **COMMON-011 [P1] 시간 표시** — 서버 UTC 시각이 사용자 로컬 시각과 상대 시간으로 정확히 표시된다.
- [ ] **COMMON-012 [P1] 정적 자산 캐시** — 새 배포 뒤 오래된 JS/CSS와 새 API 계약이 섞여 흰 화면이나 무한 새로고침을 만들지 않는다.
- [ ] **COMMON-013 [P1] 서비스 상태** — `/actuator/health/readiness`, `/api/health`, `/api/public/status`가 실제 DB·수집 상태를 구분해 반환한다.
- [ ] **COMMON-014 [P1] 실행부 격리** — 세탁·급식·알림 작업 하나의 실패가 API와 다른 scheduler 작업을 중단시키지 않는다.
