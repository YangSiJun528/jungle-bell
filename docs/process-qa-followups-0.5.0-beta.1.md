# Jungle Bell 0.5.0-beta.1 직접 QA 후속 작업

## 목적

`v0.5.0-beta.1` 직접 QA에서 확인된 문제를 재현하고 수정한 뒤, 기존 정상 기능까지
회귀 검증한다. 이 문서는 임시 작업 기록이며 아래 항목을 모두 완료하면 저장소에서
삭제한다.

## 실행 정보

- 기록일: `2026-08-19` KST
- 기준 커밋: `e5aab73d3c2ca39aef6abe59db4df9173fd4ccd1`
- 기준 버전: `0.5.0-beta.1`
- 환경: macOS PC 앱, 설치형 PWA, 일반 웹
- 증거: 사용자 제공 모바일 연결 화면 캡처 `872 × 732`
- 인증 원문, 연결 코드, Push 구독 정보는 기록하지 않는다.

## 문제와 완료 조건

### QA-001 학습 시작·종료 용어 통일

- [ ] 출석 화면의 `오전 출석`을 `학습 시작`, `오후 출석`을 `학습 종료`로 표시한다.
- [ ] 출석 알림, 설정, 알림함, 트레이 등 사용자에게 보이는 같은 의미의 문구도
  `학습 시작`과 `학습 종료`로 통일한다.
- [ ] 내부 API·DB wire 이름을 불필요하게 바꾸지 않고 기존 데이터와 동작을 유지한다.

### QA-002 출석 확인 기수 전환 일관성

- [ ] 사용자가 선택한 기수와 출석·D-Day·기수 선택 UI가 항상 같은 값을 가리킨다.
- [ ] 선택 저장과 새 기수 데이터 재조회가 완료되기 전에 다른 기수의 결과를 완료된
  상태처럼 표시하지 않는다.
- [ ] 실패 시 이전 확정 선택을 유지하고 재시도할 수 있다.

### QA-003 작은 PC 화면의 모바일 연결 레이아웃

- [ ] QR, 수동 연결 코드, 승인 요청과 버튼이 작은 폭에서도 카드 밖으로 나가지 않는다.
- [ ] 기기명과 확인 코드가 긴 경우 줄바꿈 또는 말줄임이 적용된다.
- [ ] 승인·거절·새 코드 버튼이 겹치지 않고 키보드와 포인터로 조작 가능하다.

### QA-004 PWA 테스트 Push 전달

- [ ] Push 권한과 구독이 완료된 PWA에서 테스트 알림 버튼을 누르면 요청 상태가
  복구되고 실제 Push와 알림함 항목이 생성된다.
- [ ] 처리 중 버튼 비활성화는 성공·실패 후 반드시 해제된다.
- [ ] Worker 전달 실패는 재시도 또는 사용자가 이해할 수 있는 오류로 표시한다.
- [ ] PC 테스트 알림과 기존 fan-out·ack 동작을 회귀 검증한다.

### QA-005 PC·PWA 홈 출석 요약 복구

- [ ] 인증된 PC와 연결된 PWA 홈의 주 카드는 광고가 아니라 출석 요약을 표시한다.
- [ ] 학습 시작·종료 상태와 선택 기수의 D-Day를 함께 표시한다.
- [ ] 일반 웹의 공개 홈과 인증되지 않은 전역 게이트는 기존 동작을 유지한다.

### QA-006 워시타워 알림 선택과 확정

- [ ] 워시타워 번호를 선택한다.
- [ ] 세탁기 또는 건조기를 선택한다.
- [ ] 알림 시점을 `N분 남음`, `완료 예상`, `확장 완료` 중에서 선택한다.
- [ ] 확정한 조건이 저장되고 해당 조건에 맞는 알림만 생성된다.
- [ ] 추가·삭제와 PC/PWA 설정 공유를 회귀 검증한다.

## 기존 정상 기능 회귀 기준

- [ ] PC 알림과 PC 테스트 알림
- [ ] PC/PWA 미인증 상태의 전역 사용 차단
- [ ] PC에서 PWA 코드 연결과 QR 연결
- [ ] 출석 상태 조회
- [ ] 세탁실 오류·위험 표시
- [ ] 일반 웹에서 제공하는 공개 기능

## 종료 조건

1. 각 문제의 실패 테스트를 먼저 추가한다.
2. 문제별 자동 테스트와 영향받는 기존 기능 테스트를 통과한다.
3. `frontend`에서 `npm run verify`를 통과한다.
4. React Doctor 변경 범위 점수가 회귀하지 않는다.
5. 실제 PC/PWA 화면을 캡처해 작은 폭과 주요 상태를 직접 확인한다.
6. 변경사항을 원인 단위로 커밋한다.
7. 모든 항목이 충족되면 이 문서를 삭제하고 삭제 자체를 마지막 커밋으로 남긴다.
