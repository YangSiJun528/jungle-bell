# 대시보드 데이터 후속 개선 인수 기준

문서 유형: process.

이 문서는 급식 기록·세탁 상태·출석 및 설정 후속 개선의 임시 인수 기준이다.
각 항목은 자동 테스트와 실제 데이터로 검증한다. 완료 후 작업 트리에서는 제거하되
Git 이력에는 남긴다. 외부 상태 때문에 완료할 수 없는 항목은 원인과 확인 증거를
기록한 뒤 나머지 작업을 계속한다.

## 기능 인수 기준

- [x] 지난 급식 기록의 수동 `이전 기록 더 불러오기` 동작을 제거하고, 사용자가
  달력을 다른 달로 이동할 때 해당 달에 필요한 기록을 자동으로 조회한다.
- [x] `7월 2주차 식단표`를 포함한 과거 주간 식단표의 원본·D1·R2·OCI 수집 경로를
  확인하고, 실제 보관 데이터가 있으면 지난 기록 화면에 표시한다. 원본 자체가
  없으면 확인한 저장소와 조회 결과를 기록한다.
- [x] 홈의 `남성 가능`·`여성 가능` 수치가 공개 세탁 상태에서 올바르게 계산되고
  실제 v2-test 응답과 화면에서 일치한다.
- [x] 출석 페이지에도 현재 선택 기수의 D-Day 카드가 표시된다.
- [x] 연결된 모바일 조회가 성공했지만 목록이 비어 있으면 오류가 아니라 정상적인
  미등록 상태로 안내한다. 인증·네트워크 실패와 빈 응답은 구분한다.
- [x] 워시타워 상태 카드 상단 범례의 경고 뱃지는 아이콘 없이 표시한다. 실제 경고
  기기 셀의 접근 가능한 경고 표시는 유지한다.
- [x] 동일한 수동 갱신·빈 상태·오류 상태에 쓰는 사용자 문구를 화면 전체에서
  일관되게 정리한다.
- [x] 데스크톱 설정에서 LMS 기수를 선택할 수 있고, 선택값은 검증된 로컬 앱 설정에
  저장되어 checker와 출석·D-Day 계산에 함께 적용된다.
- [x] macOS에서 서버용 PC 자격증명 때문에 한 작업에 키체인 인증을 두 번 요구하지
  않는다. 시작·등록·회전·초기화 경로의 vault 접근 횟수를 테스트로 고정하고 실제
  앱 실행에서 확인한다.

## 검증 및 배포 기준

- [x] 프런트엔드·서버·Rust 테스트, 타입 검사, 앱과 Jobs 빌드가 통과한다.
- [x] React Doctor 점수가 작업 전 기준인 77점보다 낮아지지 않는다.
- [x] 실제 Tauri 창 크기에서 화면을 캡처해 잘림과 상태 오류를 확인한다. 운영체제
  제약으로 캡처할 수 없는 화면은 원인과 보완 테스트를 기록한다.
- [x] v2-test Worker와 필요한 OCI Jobs를 배포하고 공개 API·정적 화면·수집 로그를
  검증한다.
- [x] 프로덕션 설정·인증·데이터 저장소가 유효하면 같은 검증 절차로 배포한다.
  유효하지 않으면 배포를 강행하지 않고 차단 원인과 확인 증거를 기록한다.
- [x] 임시 캡처 코드를 제거했다. 이 결과를 Git 이력에 남긴 다음 이 문서를 제거하고
  최종 정리 커밋을 만든다.

## 검증 결과

검증 시각은 2026년 8월 13일(KST)이다.

- 월별 급식 기록 API `?month=2026-07`은 7월 게시물 45건을 반환했고, 모든 게시물의
  게시 시각이 7월 범위 안이며 `nextBefore`는 `null`이었다.
- D1에는 2026년 7월 6일부터 8월 10일까지 주간 식단표 메타데이터 6건이 남아 있었다.
  7월 주차를 포함한 과거 이미지 5건은 OCI 수집 실패가 아니라 R2 객체 누락이었다.
  여전히 유효한 카카오 원본을 내려받아 SHA-256과 바이트 수를 D1 메타데이터와
  대조한 뒤 v2-test R2에 복구했다. 배포 후 6건 모두 HTTP 200과 정확한 바이트 수를
  반환했다.
- v2-test 세탁 응답은 `expectedRefreshIntervalSeconds=300`, 남성 5회·여성 3회 시작
  가능, 양쪽 `reliable=true`였다. 배포 화면에서도 같은 수치와 기본 너비 3열 카드,
  아이콘 없는 상단 경고 뱃지를 확인했다.
- 모바일 목록 API의 실제 응답은 `{devices: [...]}` 봉투다. 클라이언트가 이를 배열로
  오인하던 파서를 수정했고 `{devices: []}`를 정상 빈 목록으로 고정했다. v2-test D1은
  전체 계정 기준 활성 모바일 세션 2건이므로, 특정 계정의 빈 목록은 전역 데이터
  부재나 서버 오류가 아니라 정상적인 미등록 상태다.
- macOS 앱은 ad-hoc 서명(`TeamIdentifier` 없음)이라 재빌드 후 Keychain 접근 제어가
  안정적이지 않았다. macOS·Linux는 앱 전용 mode 0600 원자적 파일, Windows만
  Credential Manager를 사용하도록 바꿨다. 앱을 두 번 다시 시작해 두 번 모두
  `server credential uses private app storage` 로그를 확인했고 설치 ID와 세션 파일은
  각각 `-rw-------`였다. 불일치한 기존 설치 ID는 삭제하지 않고 캡처 폴더에
  백업한 뒤 새로 등록했다.
- `cargo tauri dev`가 주소 환경 변수 없이 종료되는 별도 문제도 발견했다. 개발
  빌드는 v2-test Worker를 기본값으로 사용하고 릴리스 빌드만 명시적
  `JUNGLE_BELL_DATA_API_URL`을 강제하도록 수정했으며 실제 앱 기동으로 확인했다.
- 검증 결과는 웹 79개 파일·371개 테스트, 서버 37개 파일·271개 테스트, Rust
  185개 단위·2개 통합 테스트 통과다. 앱·사이트·Jobs 빌드와 Rust fmt·Clippy도
  통과했다. React Doctor는 79점으로 기준 77점보다 높다.
- 캡처 결과는 `/tmp/jungle-bell/20260813-001950-0c8e189/`에 있다. 실제 1180×780
  Tauri 홈과, 같은 너비의 실제 v2-test 세탁·급식 전체 화면을 확인했다. 최종
  재기동 뒤 macOS 세션이 잠금 화면으로 전환돼 출석·설정 네이티브 캡처는 운영체제에
  의해 흰 화면으로 마스킹됐다. 해당 화면은 컴포넌트·도메인 테스트로 보완했고
  임시 진단 코드는 모두 제거했다.
- v2-test Worker 버전 `2a496b4b-06bd-4fe0-9ca9-3e42d6f995ec`을 배포했다.
  이번 변경에는 Jobs 코드가 없어 OCI 이미지는 교체하지 않았다. 배포 뒤 기존 Jobs의
  laundry·meals 세 소스 성공 시각이 계속 갱신되고 연속 실패가 모두 0인 것을 확인했다.
- 프로덕션은 `wrangler.api.jsonc`의 D1 `database_id`가 여전히
  `00000000-0000-0000-0000-000000000000`이다. 유효한 운영 D1이 없으므로 배포를
  강행하지 않았다.
