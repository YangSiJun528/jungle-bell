# Codex 메인 에이전트 작업 안내

> 문서 유형: 방법 안내(how-to guide)

메인이 구현·수정 작업을 시작할 때 읽는 전용 안내입니다.
하위 담당자에게는 작업의 목표·범위·완료 조건과 필요한 진단·검증만 전달하며,
이 안내 전체를 읽도록 요구하지 않습니다. 역할 설정과 공통 협업 절차는
[하네스 사용 안내](guide-codex-harness.md)를 참고합니다.

## 요구사항과 완료 조건 확인

메인은 구현·수정 작업을 시작할 때 목적·범위·완료 조건을 파악하고, 완료 조건을
테스트·검사 명령 또는 관찰 가능한 결과와 연결합니다. 해석에 따라 결과가 크게 달라지는
부분은 구현 전에 사용자에게 권장안과 대안의 차이를 짧게 제시해 질문합니다.
코드·문서에서 확인할 정보는 직접 조사하고, 사용자만 정할 수 있는 요구사항은 먼저 묻습니다.
영향이 작고 되돌리기 쉬운 선택은 가정을 밝히고 진행하며, 이미 합의한 조건은 다시 묻지 않습니다.

## 반복 실패 대응

직접 작업하거나 담당자의 실패 보고를 받았을 때, 예상하지 못한 실패로 진행이 막혔다면
원인 가설과 최소 실험을 정합니다. 새 근거 없이 같은 수정·명령·위임을 반복하지 않습니다.
같은 문제에 같은 접근으로 2회 연속 새 증거나 원인 후보의 축소가 없으면, 기존 역할·작업 범위
안에서 가설·재현 방법·도구 등 접근을 바꿉니다. 명령 실패 횟수가 아니라 진전 없는 시도를 세며,
담당자를 바꿔도 같은 접근의 시도는 이어서 셉니다.

접근을 바꿔도 진전이 없고 검증할 다른 경로가 없으면 해당 경로를 중단하고, 시도한 내용·확인된
사실·막힌 이유·권장 다음 단계를 정리합니다. 사용자 결정·인증·권한·외부 준비가 필요한 막힘은
재시도 횟수를 채우지 않고 바로 질문합니다. 막힌 부분과 독립적인 작업은 계속합니다.
